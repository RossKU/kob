## 2. Invariants (P-list)

"Maker" is the order's owner key; "filler" is anyone who spends an order without the maker's signature (matcher, keeper,
refunder, router keeper, attacker).

| | Invariant |
|---|---|
| P1 | **Maker value.** A fill never pays the maker less (ask side) or charges it more (bid side) than its terms allow: price, band or auction at the CLTV-proven time, all-in with the tip, `quoteOf` rounded in the maker's favour, multiply first; any overflow fails the script. Splitting fills cannot farm rounding (ceil is superadditive, floor subadditive). |
| P2 | **Custody exactness.** An ask-side order's custody is a genuine holder of its token's program (P2SH + template hash), owned by the order's covenant id (scheme 0x04 / KRON id_type 2), borrow disabled, of the order's extension commitment, holding exactly `amountLeft`; every token output the order allows is pinned (amount, owner, scheme, template, covenant id). Bid-side orders own no tokens. |
| P3 | **Strays inert.** Tokens sent to an order's covenant id cannot be taken by a filler: fills and updates refuse any token input owned by the order other than its custody (unrolled scans of 8 KCC-20 / 4 KRON slots, more inputs refused), refunds refuse token inputs; only the maker's cancel moves strays. |
| P4 | **Anti-aliasing.** No output satisfies two obligations: payouts at the order's own input index, IOC returns at the custody's input index, exits as fresh genesis outputs keyed by the entry's outpoint, exactly one continuation per covenant id; every pinned output names a distinct owner. |
| P5 | **Authority.** Only the maker cancels or amends (65-byte signature, SIGHASH_ALL, `checkSig`); permissionless paths (fill, refund, kill, update, merge, expire) pin every output that is not the filler's own. |
| P6 | **Time.** CLTV / CSV only as "not earlier than": activation, expiry, IOC kill, 90-day idle, TWAP / DCA interval, auction time `t` (understating it only helps the maker), `rptUntil` from the entry UTXO's DAA, never from an argument. A time computed from a state field of ANOTHER order (the trigger evidence's `UTXO DAA + interval`) must not be shortened by that order's own state: a negative `interval` is refused (audit 2026-10-29 F1, section 12). |
| P7 | **Continuation.** A continuation is the order's own script with only the mutable windows spliced, holding at least what the rules require, one output for the covenant id; an exit is the committed state on the genuine template with its consensus genesis id recomputed. |
| P8 | **Trigger evidence.** A stop arms or trails only on a fill IN THE SAME TRANSACTION of a plain resting KobAsk / KobBid (KAS book) or KobPair (pair mode 1) of the same token(s) and scale: template hash + P2SH, first push the 8-byte `n > 0` of the evidence order's own fill entry, `n >= minTouch`, slope 0, exposed `>= minRestDaa` (UTXO + interval with `interval >= 0` required (F1, 2026-10-29), activeFrom, the ask custody's DAA), the ask custody authenticated as a holder of the token's program (`8f5784f`); read, never consumed; the order's own counterparty is never its evidence. |
| P9 | **Repeat-IFD binding.** Entry and booked exit cross-check each other (merge argument `-(i·2^53 + n)` both ways, the exit's immutable state bytes, parent, rate, scale, commitment, `n < 2^53`); a look-alike exit can only give; a merge never costs the entry. |
| P10 | **Resource bounds and liveness.** No obligation sits in an unscanned slot; `minFill` bounds the fills, carriers and deliveries a filler can force; keeper tips are taken only on a legitimate arm or trail and never from the buying budget; KIP-9 dust is refused by consensus, not by the order. |
| P11 | **Cross-template / cross-family.** A state, custody or evidence of another template, family (KCC-20 3/3, public-mint, 8/8, KRON 2433 / 2732, KaspaCom) or program cannot stand in for the expected one (template hash with prefix / suffix lengths, family markers, the public-mint context field inside the pinned prefix). |
| P12 | **Encoding and malleability.** Non-minimal pushes and alternative number encodings cannot change an outcome: the engine enforces a clean stack on every input and does not require minimal numbers (at most 8 bytes), silverc dispatches on a 4-byte tag compared with `OP_EQUAL`, the evidence and merge reads need a fixed 8-byte first push, and a transaction id excludes signature scripts. |
| P13 | **Router.** The payer's outflow is bounded by the signed intent (`pay + max_extra`, or `maxSell`), the intent is the last input, the merchant gets exactly the intent's amount, and the lock comes back whole on expiry or cancel (the lock's owner, scheme, amount and commitment are pinned). |
| P14 | **Off-chain trust.** What the user signs is decoded from the exact transaction (the order button's silent pre-sign checks, the private-key signer's own decoding, the issuance confirmation), every input re-read from the node, SIGHASH_ALL only; builders refuse terms that hurt the maker; the executor cannot be made to spend the operator's funds without bound. |

## 3. Methodology

1. **Manual adversarial review** of every entry of every template against P1–P13: the KAS kinds by the coordinator, the pair
   templates and the router by a second reviewer, the KRON twins diffed against their KCC-20 originals with comments
   stripped (the differences are the token codec, the scan caps 8 -> 4 and the bid-state shifts). Engine facts were checked
   in the vendored rusty-kaspa v2.1.0 (`crypto/txscript/src/lib.rs` clean stack, `data_stack.rs` number decoding,
   `consensus/core/src/hashing/tx.rs` transaction id) and in silverc (`compile.rs` dispatch).
2. **Harness proofs** in `crates/kob-tests` (the real script engine): every suspicion was refuted in code or reproduced as a
   `run_bad` scenario.
3. **Ablation completeness** (section 6): an exact map of every `require` against the catalogs, a discovery run that deletes
   each uncovered check and records which attacks flip, then new catalog entries and scenarios until every check has one.
4. **c6 fuzzer** (section 7): long runs on the KAS-kind seeds and on the pair seeds, above the previous budgets.
5. **Live attacks on testnet-10** (section 8): crafted attack transactions against real orders with separate attacker keys.
6. **Off-chain review** (P14): the wallet decode against a hostile indexer, executor API or registry; builders and codec
   against the covenants; the keeper subsidy and replace-by-fee.

## 4. Summary of results

* Manual review of the 15 templates and the router: no theft, overcharge or authority bypass. One Low on-chain finding
  (AUD-EXT, trigger evidence does not compare the KCC-20 extension commitment), mitigated off chain; its covenant fix came
  with the order template version after the report (`6276d5c`, section 11).
* Ablation: the KAS-kind catalogs left more than half of their templates' `require` lines without an entry, KobAsk's and
  KobBid's core checks included, and the tool's coverage diff overstated coverage (AUD-COV). Closed by this audit: an exact
  coverage checker (`tools/ablation/coverage.mjs`) and 572 new entries (558 confirmed, 14 defence-in-depth held); 35 of the
  1,159 `require` lines are left without a mutation, each documented as unwitnessable.
* c6 fuzzer: 4,400,000 KAS-kind mutants (1,380,941 accepted) and 3,700,000 pair mutants (867,837 accepted), **0 findings**.
* Live TN10: **43 crafted attacks, all rejected by the node for the right reason** (covenant failure, CLTV, or KIP-9 mass),
  0 accepted; 33 / 35 honest controls accepted (the two others expected). A contaminated KCC-20 genesis is accepted on chain
  (residual risk 2).
* Off chain: one Medium (AUD-SUB, the keeper fee subsidy had no total bound) fixed; two Low fixed (A1-1, A2-1), one Low fixed after the report (A1-2, `4b4dec5`); no way found
  for a hostile indexer to make the wallet sign something other than what it shows.

### Attacks tried and refuted (summary)

Theft and overcharge: payout / delivery 1 unit short, redirected, or satisfied twice (positional rule, distinct pinned
owners); custody stand-ins (equal-amount stray: it only gives; a foreign-program or look-alike holder: P2SH + template hash;
a token of another covenant id); IOC return aliasing; continuation forgery or a second continuation; exit look-alikes
and genesis-id forgery; repeat merges naming another input, another amount, an exit at another scale, the `2^53` alias, two
exits into one entry, an exit refunding or updating next to its entry. Rounding: every ceil / floor in the maker's favour,
split fills cannot farm (superadditivity), budget and prefund ceils matched on both sides of a merge; the Rust
`quote_of`, `rpt_fill_max`, `rpt_until`, `keeper_take`, `refund_due` mirror the covenants line by line. Time: decay /
auction time understated or overstated (bounded by the lock time, only moves the price toward the maker), refunds and
kills early, `rptUntil` from an argument. Evidence: cancels or refunds disguised as fills (ground signature, extra push:
0x08 first byte + clean stack; a dispatch tag is 4 bytes compared with `OP_EQUAL`), evidence of another scale, token,
family or template, decaying evidence, below `minTouch`, not rested, the order's own counterparty, `tk` pointing at a
planted input or another order's custody. Authority: cancel with another key, another sighash type, replayed signatures.
Encoding: non-minimal numbers and pushes, negative zero, merge argument encodings. Resources: KIP-9 dust and storage mass
(refused by consensus; every pin is a lower bound a filler can top up), carrier exhaustion by partial fills, keeper tips
beyond the funded budget. Router: intent not last, outflow above `pay + max_extra`, early expiry, cancel by another key,
lock substitution. Off chain: indexer-fed input amounts (re-read from the node and committed by the sighash), sighash types,
cancel / sweep / amend built from a hostile view, change keys, token identity and homoglyphs, x402 bounds.

## 6. Ablation completeness

Tool: `tools/ablation` (`README.md`): a mutation deletes one check from a copy of the contract, the harness suites rerun,
and the entry is **confirmed** when every named attack is then accepted on every input in every template section, and
**held** (defence in depth) when the named attacks must stay rejected; a combined entry removes both guards.

**Coverage before the audit.** The new exact checker (`tools/ablation/coverage.mjs`: a `require` line counts as covered
only when some catalog edit deletes or changes that very line, LCS line diff) found 598 of the 1,159 `require` lines of the
15 templates without a mutation. The old diff counted every line between the first and the last edit of a multi-edit
entry, which overstated coverage (AUD-COV).

**Method.** A discovery run deleted each uncovered check (stray-scan slots grouped per scan) and recorded which existing
negative scenarios flipped; every flip became an entry; every check without a flipping scenario got a new `run_bad`
scenario (`NAU-*`, positive controls `PAU-*`, in new `v3_audit_*` / `*_buy_audit_*` / `*_kron` test functions, so the
existing baselines are untouched), a hold plus a combined entry, or a documented reason it cannot be witnessed.

|---|---|

| KobBid / KobBidKron | 43 / 38 -> 2 / 2 |
| KobCondAsk / KobCondAskKron | 55 / 47 -> 3 / 3 |

`KobIfdPair` (reached only with `n > 0`).

## 10. Residual risks

1. **Touch-trigger economics.** A stop arms on a resting quote at or beyond its stop that was exposed for `minRestDaa`
   (wallet default 50 DAA, 5 s) and filled for at least `minTouch`. Faking it costs only what other takers capture from that
   quote while it rests (since the order template version of 2026-10-29 it costs that: until then an evidence order carrying a negative
   `interval` counted as rested at once, so faking it cost nothing and a long `minRestDaa` protected nobody, section 12). On a thin canary market with few matchers, an attacker can arm a victim's stop cheaply and take the
   stop's fill; the loss is bounded by the victim's own stop and band. Mitigations: run the reference matcher with inventory
   (it takes mispriced resting quotes), consider a longer default `minRestDaa` for the canary, document it for users.
2. **Permissionless KCC-20 tokens.** Every KCC-20 3/3 and public-mint token is tradable without curation. The UI shows the indexer's facts as neutral
   badges (since 2026-10-26): genesis not verified, live mint authority, and the program's mint / blacklist powers; it gives no
   verdict and blocks nothing. A token whose genesis is contaminated (a mint authority outside the program, a second
   commitment) can be inflated by its creator; for such tokens the touch trigger gives no protection (units of a second
   commitment no longer arm a stop since `6276d5c`, AUD-EXT; units of the order's own commitment minted outside the program
   still can). Users must
   identify tokens by covenant id; KRON registry tokens are genesis-verified.
3. **Live coverage.** KobCondPair / KobIfdPair, and a look-alike custody whose own redeem script carries the evidence ask's id at
   the old fixed offset, were tested in the engine only (section 8).
4. **Covenant immutability.** Nothing on chain can pause or rescue an order; a defect found after launch is fixed only by new
   templates (`docs/spec/template-retirement.md`); orders on the old ones end by their makers' cancels.
5. **Operator.** The keeper subsidy window lives in memory (each restart can add one budget); keys and node availability are
   the operator's.
