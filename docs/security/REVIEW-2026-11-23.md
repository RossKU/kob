# Internal security review, 2026-11-23 (release candidate before mainnet)

This is an internal review by the author's own review process, not an independent audit. There is still no external audit of KOB
(`SECURITY.md`). This page records what was reviewed, how, and what came out of it.

## Question and target

The question was not "does the code pass a checklist" but **can real money sit in this system on mainnet**: each reviewer took the
attacker's side (someone who wants money, or wants to hurt users) and traced each attack to the exact code that stops it, or does not.

* Target: the release candidate, branch `rc` at commit `a235bed70` (master `e2ff503af` plus the automatic creator lock, a help-text
  tidy and comment-only changes).
* Trust model attacked: users hold their keys and the web app or `kob` builds what a wallet signs; order funds move only by the
  contract rules; executors (third parties, untrusted) match for a tip; the public indexer is display data and untrusted for funds;
  a Kaspa node may lie; the founder runs only the web app and the indexer and holds no user funds.
* Severity scale: Critical (user funds taken or lost without the user's key, or a signing path where a user signs away funds they
  were not shown); High (an executor's funds, funds stuck with no way out, the public indexer or site made to show false prices or
  books at scale, a key or secret exposed); Medium (griefing with real cost, denial of a public service, recoverable stuck funds,
  misleading display); Low and Info.

## Method

* **Read-only.** The reviewers read code, documents, tests, git history and the committed artifacts. Nothing was built, run or
  sent to a live service during the review; where a claim needed a test, the test was written out as text in the report to be run
  later.
* **Seven areas**, one report each:

  | Area | Scope |
  |---|---|
  | A | the on-chain contracts (order kinds, the router, the token programs, the creator locks) |
  | B | what users sign (the Rust builders, the web planners, the signer frame, the wallets, trusted data, x402) |
  | C | the kobd indexer (follower, chain proofs, processor, parsers, storage, public API) |
  | D | the executor (matcher, keepers, crash recovery, operator funds) and the tools that drive a key (`tools/mm-bot`, `tools/kob-mcp`, x402) |
  | E | the web app as a browser target (CSP, framing, sinks, logos, network and server settings) |
  | F | operations, release and the launch runbook |
  | G | a regression ledger of every earlier finding |

* **Second passes.** Areas A, B, C and D were read a second time by a separate pass with a narrower scope (A: the conditional, if-done
  and pair contracts, then the router and the token programs; B: the Rust builders, then the web signing paths; C: the processor,
  reads, parsers and storage; D: matcher allocation, keepers and crash recovery). Twelve reports in all.
* **Regression ledger (area G).** Every earlier finding of Low and above (and the cheap-to-check Info rows) from the earlier internal
  reviews (`AUDIT-2026-10.md`, the red-team reports `REDTEAM-2026-11-kaspero.md` and `redteam-coverage.md`, and the unpublished
  review notes of 2026-11-17 and 2026-11-19) was checked again against the code at `a235bed70`: **182 findings**, each marked fixed,
  accepted, partial, open, regressed or cannot tell.
* Each finding states the attacker, the precondition, the steps, what is lost, file and line evidence, a confidence (CONFIRMED when
  the code path was read end to end, PLAUSIBLE otherwise) and the smallest fix.
* Every reviewer listed what they did **not** cover; those lists are kept with the reports.

## Not covered

* No independent party reviewed anything.
* Live settings and services were not read during the review: GitHub repository settings, Cloudflare settings, the live headers and
  the public indexer's health.
* No fuzzing, mutation or engine run was done as part of this review; earlier runs are recorded in `AUDIT-2026-10.md` and
  `redteam-coverage.md`.
* Legal questions are outside it.

## Decisions recorded with this review

* **W-L4 accepted (founder decision, 2026-11-20).** The shared-ticker note in the market bar shows the warning sign alone in a
  warn-coloured pill, with a tap target that opens the sentence; the short text "Shared ticker: check the id" is its accessible name
  only. The earlier fix (`a8045862d`) showed the short text in the pill; help-tidy (`1626de2f8`) reduced it to the sign, because the
  note also shows on honest tokens that only happen to share a ticker. Accepted residual: a user who does not know the sign must tap
  it to learn that the ticker is shared. The full sentence stays on tap or Enter and in pair details.
