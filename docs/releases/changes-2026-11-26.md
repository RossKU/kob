# Changes on master, 2026-11-23 to 2026-11-26

## Summary

- These are the changes that reached master between 2026-11-23 and 2026-11-26. Mainnet has not launched; TN10 is live.
- Most of them come from a production-readiness security review in several passes. Every fix listed here is on master.
- A new generation of order templates, meant for mainnet, was switched on on TN10 on 2026-11-26.
- Creator locks now open by themselves after their date. The public API gained paging, a dust filter and read bounds.
- The wallet, the CLI, the indexer and the bots now take less on the word of one node or of the indexer.

## What you need to do

- Update the `kob` CLI and the SDKs (kob-wasm, mm-bot, kob-mcp) from master. Executors and indexers must run the
  release build.
- Orders placed on the previous templates are cancel-only: only their makers can cancel them, and no keeper refunds or
  kills them. Cancel them, or let them fill. They are listed in `docs/spec/template-retirement.md`.
- Check that `GET /v1/health` reports `template_generation` `c4539e787bb33105` (it was `2bbbdc9240abaf23`). A build
  with another value serves other templates.
- The TN10 soak tokens (TUSD, TETH, TBTC) were issued again, so their covenant ids changed. The re-issue is recorded
  in `docs/releases/tn10-2026-11-26.md`; check the whole id of a token before you trade it.
- Keeper tips and refund tips changed. Read the new values from `crates/kob-protocol/data/keeper_tips.json` and
  `crates/kob-protocol/data/pair_keeper_tips.json`; do not reuse older figures.
- Executor operators: the maintenance sale is now off by default (`--dust-sell` turns it on), and on mainnet `kobd`
  refuses to start when another account can change its program, folder, key file or configuration.

## Order contracts (the pre-mainnet template generation)

1. Every order template changed. The 22 previous templates moved to the cancel-only table, and the new generation
   is `c4539e787bb33105`.
2. Every order entry refuses a transaction on a KIP-21 user subnetwork lane. No KOB tool builds one, and the indexer no
   longer has to prove such lanes for orders.
3. A stop that takes a fill of an ask, a bid or a pair order as evidence now proves that the state of that order is
   plain data in canonical form. A hand-built order can no longer hide code in its state or swallow its code with a
   final push.
4. The cancels of the order kinds that can serve as evidence, and the refunds of the bids, refuse a signature script
   shaped like a fill. So an accepted evidence fill trades at least the stop's `minTouch` at its quote, where before a
   fill of one unit, or of none, could arm or trail a stop as if it were any size.
5. A sell order's custody must carry a zero borrow guard. A unit sent with another guard can no longer stand in for the
   custody and block the tools from ending the order.
6. A refund needs tokens left in the order. An empty hand-made sell order no longer pays its carriers to whoever
   refunds it.
7. A trailing sell stop stops at the largest stop the contracts fill (`MAX_STOP`), so it no longer trails into a state
   that can never fill.
8. Order scripts are larger, so fills cost more mass. The compute budgets, keeper tips and refund tips were measured
   again for the new scripts, and the execution mass bound of a KAS-to-token fill follows the larger ask.
9. A new lock contract, `KobLockAuto`, holds a creator's kept share until a date and then opens by itself: anyone may
    send the release, and it can only pay the creator. It returns the 1 KAS lock coin, less at most 0.03 KAS.
10. `KobLockAuto` is pinned in both deployment records and counts in the template generation. Locks made the old way
    keep working with the manual unlock.

## Wallet and signing safety

11. The private-key signing frame now signs only a closed list of transaction shapes (send, place, take, end an order,
    continue an order), judged on data the signature binds. Anything else is refused with one sentence.
12. The frame judges which orders and holdings a transaction touches from what the signature binds, not from labels
    the app supplies.
13. After one approval, a re-timed copy is signed without a new prompt only for an auction, and only when it spends
    exactly the inputs the user approved.
14. A re-timed auction is compared with what the user confirmed before an external wallet is asked to sign it.
15. Signed times (expiries, activations, auction origins, lock times) no longer come from one node's claim. The app
    uses the indexer's verified present, and the node must agree with it within 600 DAA.
16. With the indexer down, the app keeps a time witness (the last verified present, or the user's own node). Without
    one it refuses to sign money-moving times; a take of fixed-price orders needs none.
17. Every recipient, order and token on the signing screens is named by its whole id or key. A unit is a ticker or
    "token", never an id.
18. The frame answers with the id of the transaction it signed and ties a new order to the preparation it signs.
19. The confirmation and the signing frame name the network. The frame marks its network and clock labels as the
    app's word, and says whose word the KAS of unsigned inputs is and whom it pays.
20. The frame shows token amounts of spends and takes at the order's own scale, and checks the scales of a pair order.
21. A cancel, refund or claim spends the custody that the order's own state implies, never one the indexer picks. A
    spend that ends an order must release that custody or it is blocked.
22. A sweep or an amend never moves the custody of the order it keeps, and a sweep never takes a custody.
23. Every builder and verifier refuses an output that would continue an order but is a new genesis on chain, which
    would end the order and lock what it holds.
24. The 8-byte state fields are read and written as the engine's script numbers. Hostile values saturate or are
    refused instead of wrapping.
25. A creator lock counts only the class of the token the market trades; a lock of another class is not shown as the
    token's lock.
26. A cancel never leaves stray units behind silently: an unread stray list stops it, and strays it cannot move are
    named before signing.
27. Nothing an outsider sends to an order stops its maker from cancelling it.
28. An amend with a new price leaves a fixed-price order, and the decoder blocks a repriced auction that keeps its old
    schedule.
29. A one-cancels-other order's "you receive at least / pay at most" shows its true worst case, not the take-profit.

## kob CLI and builders

30. `kob token create --lock-until` makes an automatic lock by default; `--lock-manual` makes the older manual lock.
    `kob token unlock --tip` sends an automatic release as a keeper.
31. A pair market buy always waits for `--ack-market-start`.
32. A token whose decimals only the indexer names needs `--decimals N` in `kob place`, `kob send` and `kob replace` for
    an amount in whole tokens. Base units (digits followed by `base`) need none.
33. The quote token of a pair order is checked against the scale its order state commits, like the base token.
34. Every line the CLI prints passes one sanitiser, so text from outside (tickers, names, error messages) cannot add
    lines or control sequences. `--json` output stays valid JSON.
35. `kob cancel`, `sweep`, `replace`, `take` and `recover` take each custody from the order's own state as the node
    proves it. A cancel takes every unit the node shows the order owning, or stops with "run kob sweep first".
36. `kob sweep` leaves a unit that matches a custody where it is (the cancel takes it).
    `kob recover --custody-gone` was removed.
37. `kob replace --price P` writes a fixed-price order at P. A new price that crosses the checked book is
    refused unless `--crossing limit` is given; without a book the amend needs `--ack-no-guards`.
38. `kob replace --abandon-strays` lets a cancel-replace go ahead when strays would otherwise refuse it.
39. The CLI takes the chain time from the indexer's verified present and both nodes, and refuses when the nodes
    disagree.
40. The refusals of `kob replace`, `cancel`, `sweep`, `refund`, `claim`, `take` and `send` carry issue codes, in the
    text line and in `--json`.
41. `kob orders`, `kob balances` and `kob sweep --all` follow the API's cursor to the end. A list not read to its end
    is marked incomplete, and `sweep --all` then exits 1.
42. `kob recover` can cancel a partly filled Collected order, with the tokens it bought, from the node alone.

## Indexer and executor (kobd)

43. A covenant id that the node claims for an input can no longer hide a new placement from the index.
44. The payer of a fill, which drives the self-trade filter of prices and candles, is checked against its signature.
45. A payload that only starts with the KOB1 magic no longer forces a full block fetch; only a decodable record does.
46. The chain authority's copies of KOB transactions are compared with the cross-checking node. A difference applies
    nothing; when no cross-check answers for 120 s the authority goes on alone and `/v1/health` says so.
47. A dead, hung or withholding follower or chain authority is no longer reported as current.
48. Chain progress is judged every second from the verified header time of the cursor block and the local clock,
    never from what a node says about its own position.
49. No text a node sends can halt the follower. A node that reports another network is treated as unavailable.
50. Every public read takes "now" from the store's verified cursor, not from a DAA score a node only claimed.
51. KOB state is created only by native-lane transactions. A user-lane transaction can only end what the index tracks
    (`docs/spec/indexer-lanes.md`).
52. The chain proof keeps every lane a batch needs, across steps, sized to how fast the node answers, so a flood of
    lanes cannot stall it.
53. A coinbase is never read as KOB, so a block whose coinbase happens to start with the magic does not stop the index.
54. A KCC-20 order must name the extension commitment its token's holdings prove. A stray placement can no longer
    list a fake best bid or erase the token's commitment.
55. The index never lists an order whose state is not in canonical form.
56. A Collected pair sell stays proven, and listed, after a partial fill.
57. Logo votes count from an address whose KOB history is at least 7 days old and older than the token, or from an
    address that has held the token for at least 7 days.
58. Crosses between one maker's own orders no longer hide the last price, and closed candles are cached for an hour
    only while the store is caught up.
59. The executor's maintenance sale is opt-in (`--dust-sell`, `KOB_DUST_SELL`). By default holdings are only merged.
    When on, its price floor counts only asks that buyers could take for at least a minute.
60. Every executor job is held to a fee bound on its built transaction before it is signed; a matcher batch above
    `max_tx_fee` waits for the next tick.
61. An order the script engine refuses is set aside until its state changes, so one bad order cannot stall the
    matcher. Pair netting cannot take the planning time of the other books.
62. Executors release due automatic creator locks for a 0.01 KAS tip, and the release keeper counts only a tip paid to
    the operator's own key.
63. `kobd --executor`, `match`, `keep` and `withdraw` check their program, folders, key file, policy and configuration
    first. On mainnet they refuse to start when another account can change them; on TN10 they log it.
64. On Windows a NULL DACL counts as Everyone, and `kobd` and `kob` load system DLLs from System32 only. On Unix the
    umask allows no group or other write.
65. `kobd match` and `kobd keep` with `--state-dir` keep their journal, inventory use and subsidy window there. A
    damaged `inventory-use.json` keeps nothing until it reads.
66. The keeper fee subsidy is one documented default: at most 1 KAS per rolling 24 hours.
67. A store swap during migrate or vacuum is crash-safe, and an interrupted one is undone.
68. The setup prompt and `--help` say that the x402 facilitator is experimental.

## Public API

69. New: `GET /v1/tokens/{covenant_id}` returns one token's view even when the token list's cut does not reach it.
70. New: `GET /v1/pairs/{base}/{quote}/orders` lists a pair's live orders, newest first, paged by cursor.
71. `GET /v1/tokens` is paged (`cursor`, `limit` up to 2,000, `next_cursor`) and orders tokens by market presence.
    `GET /v1/pairs` stays a bare array and marks a cut scan with the header `x-kob-truncated: 1`.
72. `GET /v1/token-utxos` paging always advances, and `order=amount` lists an owner's live units of one token, largest
    first.
73. Book rows and order views carry `fillable_now`: what one fill can take now. Sum it, not `amount_left`, for depth.
74. A book shows an order only as far as one fill can take it, by the matcher's own fill rules at the order's least
    favourable quote in its window. An order no single fill can take is not in the book.
75. Dust (an order one fill can take less than half the listing minimum from) stays fillable but leaves the default
    book; `include_dust=true` shows it and `dust_orders` counts it.
76. A curve shows its depth as the sequence of its successive smallest valid fills.
77. Every public read has a work budget; a read past it is answered `503 read_budget`. Lists are bounded and say when
    they are cut.
78. One client may have 8 requests in flight; a further request waits up to 2 s without holding a server slot.
    `/v1/health`, `/v1/health/ready` and `/v1/metrics` answer from memory outside the request cap.
79. `/v1/health` documents `template_generation` and `cancel_only_generations`, and reports `cursor_time_unix_ms`,
    `authority_pace`, `cross_check_alone` and the chain-proof and lane-load counters.
80. `lag_seconds` is the age of the cursor block by the local clock; `lag_daa` is shown for information only. The
    WebSocket health frame sends the present DAA score and the lag.
81. Charts answer in whole buckets, and pair candle volume comes from aggregates the indexer keeps.
82. An order view can carry `lane_end` (an order closed by a user-lane spend), `strays_total` and `children_total`.

## Web app

83. Create token locks the kept share automatically; Settings has "Manual unlock", and Portfolio releases a due
    automatic lock without a signature.
84. Field and dialog explanations moved behind a "?" next to the title or label.
85. A deployment can show one incident banner from `config.json` (`incident`). It blocks nothing.
86. Without the indexer, the app can cancel a partly filled Collected order with its bought tokens from the node, and
    the standalone book follows a Collected bid through sweeps, amends and claims.
87. The automatic standalone mode starts at an indexer lag of 120 s, ends at 100 s, and lasts at least 30 s; re-entry
    backs off while the indexer is down.
88. The app keeps at most 6 indexer reads in flight per base URL (5 over plain HTTP), and the ticket's reads go first.
89. The node-checked book prices each order at its quote now. A side the check could not read stops the order; the
    check waits up to 20 s for a slow indexer.
90. A hung, stopped or lagging indexer is not used, and confirmations follow the verified cursor.
91. A ticker that reads as KAS, or that is not plain ASCII, is always printed with the token id. A bridge minter is
    shown as a live mint authority, and no text asserts backing.
92. The creator-hosted logo of a token the wallet holds or has orders in is gated, so a creator cannot tie a holder's
    address to an IP by sending one unit or placing one small order.
93. The ticket's help says when an order or slice is dust, from the indexer's own listing minimum.
94. A buy order's budget is what its fills may spend; its refund tip is no longer shown as taken from it.
95. Many active orders of one token no longer shut the pair ticket; the pair ticket reads the pair's own order route.
96. A token missing from a cut token list is read by its id, so a token opened by id or link stays tradable.
97. A take step the node accepted reads "sent", not "filled", until a block holds it.
98. Settings and the disclaimer say that an indexer can leave orders out, and that the remedy is your own Kaspa node
    and indexer.

## Tools and SDKs (mm-bot, MCP, x402, kob-wasm)

99. mm-bot tracks every quote by its own outpoint through the node. The node, not the indexer, ends a quote, and an
    order's own transaction is in flight until the node shows it.
100. mm-bot has no token USD fallback by default: a stale USDC rate idles the bot until the rate is live again.
101. mm-bot quotes are post-only (`--crossing reject`) and never rest as auctions. An amend refused twice in a row
     cancels and re-places the quote.
102. mm-bot does not adopt an order on its key that it did not place, and `drop` keeps a record and needs `--force` for
     a doubtful order.
103. mm-bot refuses a peg band wider than half the spread, needs a JSON wRPC node on mainnet, and refuses an `http://`
     indexer there.
104. mm-bot can quote whole-fill asks (`quotes.askPartialFills: false`), which the node alone tracks.
105. kob-mcp checks place, replace and claim-and-sell with one guard and tip caps, and refuses a priced write without a
     reference price it can trust.
106. kob-mcp values book rows at what a taker can fill now and leaves dust out of the depth.
107. kob-mcp has a `kob_sweep` tool, so strays cannot block `kob_cancel` and `kob_replace` for good.
108. x402: an invoice keeps a bounded number of released payments. The profile says to run the facilitator on your own
     node; x402 is experimental and outside the launch review.
109. kob-wasm gains the creator lock kind and program, `buildRelease`, and `genesisCovenantId`.

## Known limits that stay

- No external audit: the contracts, token programs and apps were reviewed internally only.
- A stop's evidence can be a self-trade: a threshold raises the capital at risk (`minTouch` at the quote for the rest
  time), not its cost.
- A fill of an order past its expiry or idle limit, not yet refunded, still counts as touch evidence. KOB's own
  executors arm only with fills of live orders.
- A trailing stop's ratchet is capped only by its take-profit; a maker-set ceiling needs a later template change.
- `KobBid`'s refund slot accepts any input without a covenant id; no KOB script combines with a bid that way.
- A repeating sell-first pair if-done entry can stall on its prefund's rounding. Nothing is lost; the maker can cancel.
- On the web, a market, close or streaming order starts from the best price the indexer shows. Your own node and
  indexer remove that reliance.
- Without the indexer, the search for a partly filled Collected order is bounded, and a claim needs the indexer.
- Expiry is soft: the chain cannot stop a fill of an expired order until a refund spends it.
