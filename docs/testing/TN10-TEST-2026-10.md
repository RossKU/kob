## Findings

**F-1 (LOW, FIXED in d00e5e3) — `add-program` rejected the upstream Kasseal public-mint artifact schema.**
Feeding the pinned upstream artifact `contracts/third-party/kcc20-reference/public-mint.artifact.json`
to `kob registry add-program` fails with `program profile …: artifact json: missing field
compiler_version at line 1848 column 1`. Cause: that file is an Argent app-bundle artifact (top-level
keys `schema_version, id, generator, app, dependencies, root, modules, argent, sil_abi`), not a silverc
compiler artifact (`schema_version, compiler_version, structs, contracts`) that the `add-program`
artifact parser expects. Repro: `kob registry add-program contracts/third-party/kcc20-reference/public-mint.artifact.json`.
Impact: low — the KOB-side silverc artifact (`contracts/artifacts/KCC20PublicMint.json`) and the raw
redeem-script path both work and derive the correct hash `734850b0`; the public-mint program is already
embedded and reviewed. The error message names a missing field rather than "unsupported artifact
schema".
**Fixed in d00e5e3:** `add-program` now detects an Argent app bundle (`sil_abi` member, no top-level `contracts`),
reads its `sil_abi` as the compiler artifact, selects the one contract with the KCC-20 draft entry pair, and accepts
the bundle's zero placeholder instance for the context field (Argent schema only). The upstream file now derives the
embedded `KCC20PublicMint` profile (hash `734850b0`, layout 34+112+3885); test
`add_program_accepts_the_upstream_argent_artifact` in `kcc20_reference_tests.rs`.

No defect was found in the roll, the order engine, the confirm screen, x402, or the registry derivation.
