# Optional batch-leader extension of KCC-20 (prototype)

Not upstream, not audited, not used for issuance. Proposed in 2026-11 as a separate, optional KCC on top of KCC-20
(earlier discussion: kas-smiths KCC-20 thread, posts #74 to #76).

**Problem.** A KCC-20 transaction takes at most 3 token inputs, so merging 70 token UTXOs into 1 takes 35 transactions.

**Idea.** Holders stay on the 3 / 3 program. A token may commit, at genesis, to one batch-leader template. That
leader holds no tokens and moves many holder UTXOs in one transaction. Each holder still requires its own owner's
authorisation, and accepts as leader only its own template or the committed one.

## Files

| File | What |
|---|---|
| `KCC20Opt.sil` | Holder program: the standalone reference [`KCC20Ref.sil`](../../../kcc20/KCC20Ref.sil) plus the leader commitment (`B_TPL` / `B_PRE` / `B_SUF`; all zeros = none) and the leader check in the delegator path. Generated by `kob_protocol::kcc20::kcc20_opt_holder_source` |
| `KCC20Batch.sil` | Batch leader: amount 0, 16 slots. `batch` moves 1..16 holder inputs to 1..16 outputs (conservation, KCC-20 per-output rules); `clone` gives anyone a leader from the public seed; `retire` returns its carrier KAS |
| `KCC20P2.sil` | Earlier form of `KCC20Opt` without the all-zeros switch, kept as a measurement |
| `*.ctor.json` | Example constructor arguments the build compiles with (`KCC20Opt`: the disabled instance) |

## Numbers

Measured against rusty-kaspa v2.1.0 per-transaction limits; fee = max(compute mass, 2 x bytes) x 100 sompi.

| | Standard 3 / 3 | With leader commitment |
|---|---|---|
| Holder program | 2,915 B | 2,934 B |
| 1 -> 1 transfer | 0.00667 KAS | 0.00671 KAS |
| 70 UTXOs -> 1 | 35 transactions | 16-slot leader: 5 batches; 70-slot leader: 1 batch (the compute limit). Plus one `clone` for a wallet without a leader |

The full tables are in [`docs/spec/kcc-conformance.md`](../../../../docs/spec/kcc-conformance.md) section 6.

## Tests

```sh
cargo test -p kob-tests --test kcc20_opt_tests                      # lifecycle, batches, negative cases
cargo test -p kob-tests --test kcc20_opt_tests -- --include-ignored # also the batch capacity sweep (N-slot leaders)
cargo test -p kob-tests --test kcc20_conformance_tests              # KCC-20 vectors on KCC20Opt, enabled and disabled
```

The negative cases include: tokens created or lost (conservation), a holder signed by the leader's key instead of
its owner, foreign and `OP_TRUE` leaders, a leader of another template, a leader created after genesis, 17 holder
inputs, the wrong signer, and a leader not at the covenant's first input.

Not done yet: the same extension on the published `KCC20PublicMint` build (`argent-lang/kcc20-reference`).
