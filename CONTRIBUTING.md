# Contributing

Thanks for looking. KOB is pre-audit and moves quickly; small, focused changes with tests are
the easiest to review. For anything that changes a contract, the protocol encoding or a
specification, please open an issue first.

## Build and test

Rust 1.94.0 is pinned by `rust-toolchain.toml` (rustfmt, clippy and the
`wasm32-unknown-unknown` target come with it). rusty-kaspa is a git dependency at tag `v2.1.0`.

```
cargo fmt --all --check
cargo clippy --locked --all-targets -p kob-protocol -p kob-wasm -p kob-executor -p kob-cli -p kob-tests -p sil2argent -- -D warnings
KOB_SKIP_NETWORK_TESTS=1 cargo test --workspace --locked      # the live TN10 tests need a testnet node
scripts/build-contracts.sh --check                              # committed artifacts reproduce
scripts/build-wasm.sh --install-bindgen --test                  # wasm bindings + node golden-vector tests
```

Web UI (Node >= 22): `scripts/build-wasm.sh --install-bindgen --web --slim` at the repo root, then from `web/`:
`npm ci`, `npm run fetch-sdk`, `npm run build:wasm -- --copy`, `npm run typecheck`, `npm test`,
`npm run e2e`. `.github/workflows/ci.yml` is the authoritative list of what must pass.

## Rules of the road

* **Contracts.** `contracts/**/*.sil` are hand-written. After changing one, run
  `scripts/build-contracts.sh` to rewrite the artifacts and `SHA256SUMS`, and commit them with
  the source. CI fails if they do not reproduce. Every new check in a contract needs a positive
  and a negative test in `crates/kob-tests`; the ablation runner (`tools/ablation`) shows
  whether a check is what actually rejects the attack.
* **Generated files.** `contracts/argent/kob_router.ag` is generated by
  `tools/router-gen/gen-router.sh`; edit the generator, not the output. Golden vectors are
  regenerated with `KOB_REGEN=1` (see `README.md`).
* **Vendored code.** `vendor/` and `contracts/third-party/` keep their upstream licences and
  provenance notes (`UPSTREAM.md`). Do not edit them in passing.
* **Secrets.** Never commit keys, mnemonics or `.env` files. Test keys must be obviously fake
  and labelled as test keys.
* **Licence.** By contributing you agree that your contribution is licensed under the ISC
  licence of this repository (`LICENSE`).

## Commit style

One logical change per commit. Subject line: `area: what changed and why it matters`, lower
case after the colon, no trailing period, e.g. `executor: unknown submit outcome is tracked and
resent`. Use the area name of the crate, tool or directory (`kob-protocol`, `web`, `contracts`,
`docs`, `x402`, ...). Explain the reason in the body when it is not obvious. Keep formatting
changes separate from behaviour changes.
