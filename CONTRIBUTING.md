# Contributing

Thanks for looking. KOB is in open review and moves quickly. Small, focused changes with tests are the easiest to review.
For a change to a contract, the protocol encoding or a specification, please open an issue first, in the
[issue tracker](https://github.com/RossKU/kob/issues).

## Build and test

Rust 1.94.0 is pinned by `rust-toolchain.toml`. rustfmt, clippy and the `wasm32-unknown-unknown` target come with it.
rusty-kaspa is a git dependency at tag `v2.1.0`.

```
cargo fmt --all --check
cargo clippy --locked --all-targets -p kob-protocol -p kob-wasm -p kobd -p kob-cli -p kob-tests -p sil2argent -- -D warnings
KOB_SKIP_NETWORK_TESTS=1 cargo test --workspace --locked      # the live TN10 tests need a testnet node
scripts/build-contracts.sh --check                              # committed artifacts reproduce
scripts/build-wasm.sh --install-bindgen --test                  # wasm bindings + node golden-vector tests
```

The web UI needs Node >= 22. Run `scripts/build-wasm.sh --install-bindgen --web --slim` at the repo root. Then run these from `web/`:

```
npm ci
npm run fetch-sdk
npm run build:wasm -- --copy
npm run typecheck
npm test
npm run e2e
```

`.github/workflows/ci.yml` is the authoritative list of what must pass. Besides the commands above, it also runs:

- `scripts/build-deploy.sh testnet-10 --check` and `scripts/build-deploy.sh mainnet --check`
- `node scripts/check-pins.mjs`
- `cargo deny --locked --config .cargo/deny.toml check`
- `npm audit` on the three lockfiles

**Hashes in documents.** `node scripts/check-pins.mjs` fails when a 64-hex constant in a pinned file is not a hash that the
generated artifacts carry. The pinned files are the docs, the Rust pin tables, the TypeScript SDK constants and the registry.
So editing or pasting a covenant id, a transaction id or a hash into a document fails CI with a message naming the file. Write a
placeholder (`<64 hex>`), or change the hash together with the artifact it pins (`scripts/build-contracts.sh`,
`scripts/build-deploy.sh`).

## Rules of the road

* **Contracts.** `contracts/**/*.sil` are hand-written.
  After changing one, run `scripts/build-contracts.sh` to rewrite the artifacts and `SHA256SUMS`, and commit them with the
  source. CI fails if they do not reproduce.
  Every new check in a contract needs a positive and a negative test in `crates/kob-tests`.
  The ablation runner (`tools/ablation`) shows whether a check is what actually rejects the attack.
* **Comment-only edits.** `node scripts/check-comment-only.cjs <rev> <file...>` compares each file with its version at git `<rev>`.
  It passes only when the edit changed full-line `//` comments and blank lines. Use it on every comment-only change to a
  contract or an Argent source. The rule is the one in `scripts/build-argent.sh`.
  The style rules are in "Code style" in [docs/development.md](docs/development.md).
* **Generated files.** `contracts/argent/kob_router.ag` is generated by `tools/router-gen/gen-router.sh`. Edit the generator, not
  the output.
  Golden vectors are regenerated with `KOB_REGEN=1` on the test that checks them, for example
  `KOB_REGEN=1 cargo test --locked -p kob-protocol --test golden`. The same works for `budget_table`, `keeper_tips` and the
  `kob-wasm` and `kob-tests` golden tests.
* **Vendored code.** `vendor/` and `contracts/third-party/` keep their upstream licences and provenance notes (`UPSTREAM.md`).
  Do not edit them in passing.
* **Secrets.** Never commit keys, mnemonics or `.env` files. Test keys must be obviously fake and labelled as test keys.
* **Licence.** By contributing you agree that your contribution is licensed under the ISC licence of this repository (`LICENSE`).

## Commit style

Make one logical change per commit. Keep formatting changes separate from behaviour changes.

- The subject has at most 72 characters and the form `area: imperative summary`.
  - Use the name of the crate, tool or directory as the area, for example `kob-protocol`, `web`, `contracts`, `docs` or `x402`.
  - Example: `executor: resend a submit whose outcome is unknown`.
- A blank line follows the subject.
- The body is wrapped at 72 columns. It carries the reason, the measurements and the history that used to sit in comments.
